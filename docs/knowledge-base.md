# База знаний

## Структура

```
knowledge_base/
├── public/                  ← документы для кандидатов
│   ├── company.md           описание компании
│   ├── vacancies.md         открытые вакансии
│   └── process.md           этапы найма
└── private/                 ← конфиденциальные документы
    ├── employees.md         справочник сотрудников
    ├── grades.md            зарплатные вилки
    └── strategy.md          план найма 2025
```

Все файлы читаются при старте сервиса (`build_vectorstore()`) и загружаются в одну коллекцию ChromaDB.

## Механизм чанкинга

Реализован в `app/vectorstore.py`, функция `_split_markdown(text)`.

```
Параметры:
  CHUNK_SIZE    = 800 символов
  CHUNK_OVERLAP = 100 символов

Алгоритм:
  1. Разбить текст по заголовкам второго уровня (## heading)
  2. Каждая секция проверяется:
     - длина ≤ 800 → добавить как один чанк
     - длина > 800 → нарезать скользящим окном с перекрытием 100 символов
```

### Пример чанкинга

Исходная секция из `grades.md`:

```markdown
## Разработчики

- Junior Developer: 120 000 – 160 000 ₽ gross
- Middle Developer: 180 000 – 260 000 ₽ gross
- Senior Developer: 290 000 – 400 000 ₽ gross
- Lead Developer: 420 000 – 560 000 ₽ gross
```

Если эта секция ≤ 800 символов, она становится одним чанком с метаданными:

```json
{
  "document": "## Разработчики\n- Junior Developer: 120 000...",
  "metadata": {
    "file": "grades.md",
    "layer": "private"
  }
}
```

При семантически близком запросе («зарплата разработчика», «вилка Senior») этот чанк будет в top-3 результатах ChromaDB.

## Почему смешанное хранение — намеренная уязвимость

В продакшн-системе правильным решением было бы:

```python
# Правильно: фильтровать по layer при запросе
results = collection.query(
    query_texts=[question],
    n_results=3,
    where={"layer": "public"}  # только публичные документы
)
```

В этом стенде фильтр **намеренно отсутствует**:

```python
# Уязвимо: все документы возвращаются без фильтрации
results = collection.query(
    query_texts=[question],
    n_results=settings.top_k_chunks
)
```

Это позволяет приватным чанкам попадать в контекст LLM и становится основой для атаки RAG data poisoning.
