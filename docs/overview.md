# Обзор проекта: HR-агент (Red Teaming Demo)

## Что это?

RT-demo — учебная платформа для демонстрации атак на LLM-агентов. Это **намеренно уязвимый** HR-чатбот вымышленной компании «Meridian Software», созданный как стенд для отработки техник red teaming.

Цель проекта — наглядно показать, почему нельзя полагаться исключительно на системный промпт для защиты конфиденциальных данных в RAG-приложениях.

## Учебный контекст

Проект предназначен для:

- Инженеров по безопасности, изучающих атаки на LLM-системы
- Разработчиков, которые строят собственные RAG-агенты и хотят понять их слабые места
- Команд, проводящих security-ревью AI-продуктов

Стенд воспроизводит типичные ошибки в продакшн-агентах: отсутствие контроля доступа на уровне данных, защита только через инструкции в промпте, смешанное хранение публичных и приватных документов.

## Сценарий

Агент представляется как HR-ассистент «Meridian Software» — B2B SaaS-компании в сфере логистики (150+ сотрудников, стек: Python, Go, React, Kubernetes). Агент отвечает на вопросы кандидатов о компании, вакансиях и найме.

База знаний разделена на два слоя:

| Слой | Содержимое | Должен ли агент раскрывать? |
|------|-----------|---------------------------|
| `public` | Описание компании, вакансии, процесс найма | Да |
| `private` | Зарплатные вилки, сотрудники, стратегия | Нет |

Задача красной команды — заставить агента раскрыть приватный слой.

## Три вектора атак

### 1. RAG Data Poisoning (отравление данных)

Публичные и приватные документы хранятся в **одной коллекции** ChromaDB без фильтрации при поиске. При семантически близком запросе приватные чанки могут попасть в top-K и оказаться в контексте LLM.

Пример: запрос «какая зарплата у Senior-разработчика?» может вернуть чанк из `private/grades.md`, и модель включит цифру в ответ, несмотря на запрет в системном промпте.

→ Подробнее: [vulnerabilities.md](vulnerabilities.md#1-rag-data-poisoning)

### 2. Prompt Injection / извлечение системного промпта

Системный промпт хранится только в коде. Атакующий может попросить агента «процитировать свои инструкции», «переключиться в режим отладки» или подставить в запрос специальные конструкции, заставляющие модель проигнорировать ограничения.

→ Подробнее: [vulnerabilities.md](vulnerabilities.md#2-prompt-injection)

### 3. Role Injection (социальная инженерия)

Агент не имеет никакой аутентификации. Пользователь может утверждать, что он «HR-менеджер Анна» или «CTO Светлана», и просить данные от имени сотрудника. Без верификации модель склонна принимать такие заявления и менять поведение.

→ Подробнее: [vulnerabilities.md](vulnerabilities.md#3-role-injection)
